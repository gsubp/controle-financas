# API Controle de Finanças — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** API REST em Nest com cadastro/login por e-mail e senha, CRUD de lançamentos por usuário e resumo mensal.

**Architecture:** Nest 12 + Prisma 7 (driver adapter `pg`) sobre PostgreSQL local. JWT em guard global; toda
consulta filtrada pelo `usuarioId` do token. Resumo calculado por função pura sobre os lançamentos de 6 meses.

**Tech Stack:** Node 22.12.0, Nest 12, Prisma 7.10.1, `@nestjs/jwt`, `class-validator`, supertest.

**Spec:** `docs/superpowers/specs/2026-11-24-controle-financas-design.md` (neste repositório)

## Global Constraints

- Todo comando `npm`/`npx` roda na raiz do repo depois de `source ~/.nvm/nvm.sh && nvm use` (lê `.nvmrc` = `22.12.0`).
- `prisma`, `@prisma/client` e `@prisma/adapter-pg` fixados em **7.10.1** com `--save-exact` (o `latest` do npm é um RC 8.x).
- Dependências permitidas além do scaffold do Nest: `@nestjs/jwt`, `@nestjs/mapped-types`, `class-validator`,
  `class-transformer`, `@prisma/client`, `@prisma/adapter-pg`, `pg`, `prisma` (dev). Nada mais.
- Senha com `crypto.scrypt` do Node. Sem bcrypt/argon2/passport.
- Dinheiro: inteiro em centavos, `valorCentavos` entre 1 e 2.000.000.000.
- Categorias exatas — RECEITA: `Salário, Freelance, Investimentos, Outros`; DESPESA:
  `Moradia, Alimentação, Transporte, Saúde, Contas, Educação, Lazer, Outros`.
- Data `YYYY-MM-DD`, mês `YYYY-MM` (regex `^\d{4}-(0[1-9]|1[0-2])$`). Porta padrão `3333`.
- Mensagens de erro em português. Login inválido: 401 com mensagem exata `E-mail ou senha inválidos`.
- Repositório **público**: `.env` e `.env.test` nunca entram no git; `.env.example` sim, sem segredo real.
- Commits: `tipo: descrição` em português (`feat`, `test`, `chore`, `docs`, `fix`), terminando com
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Lançamento em `2026-11-30` aparece em novembro e `2026-12-01` não — fuso não pode deslocar a data (Task 3).
- Login com ` Gui@Exemplo.COM ` encontra a conta cadastrada como `gui@exemplo.com` (Task 2).
- Corpo com `usuarioId` de outro usuário é rejeitado com 400, nunca move o lançamento (Task 3).
- PATCH só com `tipo: RECEITA` num lançamento de categoria `Moradia` → 400 (Task 3).
- Token malformado (`Bearer abc`) ou assinado com outro segredo → 401, não 500 (Task 2).
